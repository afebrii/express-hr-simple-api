# Analisis Mockup & Desain Integrasi: Add / Edit Business Trips (No 2-1)

Dokumen ini berisi analisis mendalam terhadap mockup halaman **Add | Edit Business Trips** (`https://codeid.id/payroll/btrips/user/add`), pemetaan ke skema database yang telah diimplementasikan, serta penjelasan integrasi dengan REST API.

---

## 1. Analisis Elemen UI/Mockup
Berdasarkan mockup halaman pengisian perjalanan dinas, berikut adalah komponen antarmuka yang teridentifikasi:

### A. Komponen Form Pengisian
1. **Destination**: Input pencarian (*search box*) untuk menentukan rute/tujuan perjalanan dinas (Contoh mockup: `JKT-BDG JAKARTA BANDUNG`).
2. **Start Date & End Date**: Input tanggal keberangkatan dan kepulangan dilengkapi dengan ikon kalender (*Date Picker*). Contoh mockup:
   * Start Date: `12 /06 /2025`
   * End Date: `15 /06 /2025`
3. **Checklist if attend with partner**: 
   * Checkbox yang menentukan apakah perjalanan dinas dilakukan secara berkelompok/tim.
   * Jika dicentang, akan memunculkan *search input* di bawahnya untuk mencari dan menambahkan nama karyawan lain yang ikut dalam rombongan (Contoh mockup: `Aji, Budi, Charlie`).
   * Jika tidak dicentang, perjalanan dinas dianggap bersifat individu (hanya karyawan pembuat pengajuan).
4. **Purpose**: Input area teks (*textarea*) untuk menuliskan maksud/tujuan perjalanan dinas secara mendalam (Contoh mockup: `Meeting with client for development system software`).

### B. Tombol Aksi
* **Cancel**: Membatalkan pengisian dan kembali ke halaman utama daftar perjalanan dinas.
* **Save**: Menyimpan data pengajuan baru (jika konteks *Add*) atau menyimpan perubahan data (jika konteks *Edit*).

## 3. Contoh Kalkulasi Durasi & Tunjangan Otomatis
Berdasarkan data pada mockup:
* `startDate`: `'2025-06-12'`
* `endDate`: `'2025-06-15'`
* Durasi Hari = $(15 - 12) + 1 = 4$ Hari.

Backend secara otomatis mengkalkulasi tunjangan pada Service Layer sebelum menyimpannya ke database:
1. **Transport**: Rp 500.000 $\times$ 2 = **Rp 1.000.000** (pulang-pergi flat).
2. **Accommodation**: 4 Hari $\times$ Rp 350.000 = **Rp 1.400.000**.
3. **Daily**: 4 Hari $\times$ Rp 100.000 = **Rp 400.000**.
4. **Meal**: 4 Hari $\times$ Rp 50.000 = **Rp 200.000**.
5. **Total Tunjangan** = Rp 1.000.000 + Rp 1.400.000 + Rp 400.000 + Rp 200.000 = **Rp 3.000.000**.

## 4. Desain Integrasi REST API

### A. Skenario Add (Pembuatan Pengajuan Baru)
Ketika tombol **Save** ditekan pada form kosong:
* **HTTP Method**: `POST`
* **Endpoint**: `/api/v1/business-trips`
* **Headers**: `Content-Type: application/json`
* **Payload Request (JSON)**:
  ```json
  {
    "destination": "JKT-BDG",
    "purpose": "Meeting with client for development system software",
    "startDate": "2025-06-12",
    "endDate": "2025-06-15",
    "employeeIds": [100, 105, 106, 107]
  }
  ```
  *(Catatan: `employeeIds` berisi ID karyawan pembuat pengajuan beserta partner yang dipilih dari checklist, e.g. Steven King [100], Aji [105], Budi [106], Charlie [107])*

* **Response Sukses (201 Created)**:
  ```json
  {
    "success": true,
    "message": "Business Trip request submitted successfully",
    "data": {
      "businessTripId": 5,
      "destination": "JKT-BDG",
      "durationDays": 4,
      "totalAllowance": 3000000,
      "status": "New Request"
    }
  }
  ```

---

### B. Skenario Edit (Perubahan Pengajuan Pendayagunaan)
Ketika tombol **Save** ditekan pada halaman edit:
* **HTTP Method**: `PUT`
* **Endpoint**: `/api/v1/business-trips/:id`
* **Payload Request (JSON)**:
  ```json
  {
    "destination": "JKT-BDG Revised",
    "startDate": "2025-06-12",
    "endDate": "2025-06-14", 
    "employeeIds": [100, 105, 106]
  }
  ```
  *(Jika tanggal keberangkatan/kepulangan atau susunan anggota tim diubah, backend akan melakukan kalkulasi ulang secara dinamis untuk durasi hari dan breakdown nominal tunjangan, serta memperbarui tabel relasi junction)*

* **Response Sukses (200 OK)**:
  ```json
  {
    "success": true,
    "message": "Business Trip request updated successfully",
    "data": {
      "businessTripId": 5,
      "destination": "JKT-BDG Revised",
      "durationDays": 3,
      "totalAllowance": 2500000,
      "status": "New Request"
    }
  }
  ```

* **Proteksi Validasi Bisnis (di Backend)**:
  Sistem akan mengembalikan error `400 Bad Request` jika pengubahan (`PUT`) dicoba terhadap data perjalanan dinas yang statusnya sudah beranjak dari `New Request` (misal sudah `Approved` atau `Processed`).
