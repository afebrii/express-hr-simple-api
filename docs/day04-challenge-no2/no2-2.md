# Analisis Mockup & Desain Integrasi: Manager Business Trip Approval & Details (No 2-2)

Dokumen ini berisi analisis mendalam terhadap mockup halaman **Manager Business Trip Approval** (`https://codeid.id/payroll/btrips/mgr`), perubahan skema database relasional (Oracle), pembaharuan REST API, serta alur pengujian.

---

## 1. Analisis Elemen UI/Mockup
Berdasarkan mockup halaman Manager Business Trip, berikut adalah komponen antarmuka yang teridentifikasi:

### A. Filter & Pencarian
1. **Filter Periode Tanggal**: Input rentang tanggal keberangkatan dilengkapi tombol **Search**.
2. **Filter Pencarian Teks**: Input pencarian berdasarkan Nomor Perjalanan Dinas (*Trip No*) atau Nama Karyawan (*Employee Name*).
3. **Filter Status**: Dropdown pilihan status (`Approved`, `Process`, `Completed`, `Pending`).

### B. Daftar Perjalanan Dinas (Tabel Utama)
Menampilkan kolom yang sama seperti view user, namun pada kolom **Approved By** menampilkan `Waiting` (jika belum diproses) atau `Widi [ Manager ]` (nama manager penyetuju). Aksi ikon tiga titik (`⋮`) membuka menu pop-up:
* **Set Approval**
* **Details**

### C. Modal Konfirmasi Persetujuan (Confirm Approval Modal)
Terbuka ketika Manager menekan opsi **Set Approval** pada menu baris perjalanan dinas berstatus `New Request`.
* **Status**: Dropdown pilihan keputusan (`Approved`, `Pending`, `Cancel`).
* **Notes**: Textarea untuk memasukkan catatan persetujuan/alasan penolakan.
* **Cancel / Approval Button**: Tombol untuk memproses status.

### D. Modal Rincian (Details Modal)
Terbuka saat menekan opsi **Details**. Memiliki dua tab:
1. **Allowances**: Menampilkan breakdown kalkulasi tunjangan otomatis (Transport, Akomodasi, Harian, Makan).
2. **History**: Linimasa perubahan status dan tanggal proses (Diajukan, Disetujui, Diproses, Ditransfer, Selesai).

---

## 2. Perubahan Skema Database (Oracle)
Untuk mendukung input **Notes** dari atasan saat memproses persetujuan, kita menambahkan kolom baru pada tabel `business_trips`.

* **Perintah Migrasi**:
  ```sql
  ALTER TABLE business_trips ADD notes VARCHAR2(255);
  ```
* Kolom `notes` menyimpan teks catatan dari manager (maksimal 255 karakter) dan bernilai `NULL` saat pengajuan pertama kali dibuat.

---

## 3. Logika Backend & Desain REST API

Aksi konfirmasi persetujuan pada modal **Confirm Approval** diintegrasikan ke endpoint berikut:

### PATCH - Memproses Approval Manager
* **HTTP Method**: `PATCH`
* **Endpoint**: `/api/v1/business-trips/:id/approve`
* **Headers**: `Content-Type: application/json`
* **Request Body (JSON)**:
  ```json
  {
    "approvedBy": 102,
    "status": "Approved",
    "notes": "Disetujui untuk pengerjaan project software"
  }
  ```
  *(Catatan: `status` divalidasi menggunakan Zod dengan nilai `Approved` atau `Rejected`. Pilihan `Cancel` di UI dipetakan ke status `Rejected` di backend)*
* **Zod Schema (`businessTripValidation.js`)**:
  ```javascript
  const approveBusinessTripSchema = z.object({
    approvedBy: z.number().positive(),
    status: z.enum(['Approved', 'Rejected']),
    notes: z.string().max(255).optional()
  });
  ```

* **Expected Response (200 OK)**:
  ```json
  {
    "success": true,
    "message": "Business Trip approval status updated successfully",
    "data": {
      "businessTripId": 5,
  ```

## 4. Alur Demonstrasi Pengujian (Live Demo)

1. **Membuat Pengajuan**: POST ke `/api/v1/business-trips` dengan status awal `New Request` (`notes` bernilai `null`).
2. **Manager Membuka Modal Set Approval**: Mengisi keputusan `Approved` dan menulis notes: `"Disetujui untuk pengerjaan project software"`. Request PATCH dikirim ke `/api/v1/business-trips/{id}/approve`.
3. **Membuka Modal Details**: Request GET ke `/api/v1/business-trips/{id}`. Tunjukkan response JSON mengembalikan breakdown tunjangan dan riwayat timeline persetujuan lengkap dengan data `"notes"` yang baru disimpan.
4. **Proteksi**: Melakukan request PUT (Edit) atau DELETE setelah disetujui $\rightarrow$ Ditolak oleh backend (`400 Bad Request`).
