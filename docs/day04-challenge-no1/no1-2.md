# Analisis Mockup & Desain Integrasi: Manager Overtime & Approval Modal (No 1-2)

Dokumen ini berisi analisis detail terhadap mockup halaman **Manager Overtime View** (`https://codeid.id/payroll/overtime/mgr`), usulan modifikasi database (penambahan kolom `notes`), serta perbaikan skema validasi dan endpoint REST API untuk mendukung form persetujuan (*Approval Modal*).

---

## 1. Analisis Elemen UI/Mockup
Berdasarkan mockup halaman persetujuan lembur tingkat Manager, berikut komponen antarmuka yang teridentifikasi:

### A. Tabel Daftar Lembur (Manager View)
Tabel ini menampilkan pengajuan lembur dari **semua karyawan** di bawah departemen manager tersebut:
1. **Employee**: Nama Karyawan pengaju (Kolom baru yang tidak ada pada versi Karyawan biasa, contoh: `Rima`, `Ali`, `Resi`).
2. **Dates, Project, Start Time, End Time, Total Hours**: Informasi riwayat waktu lembur.
3. **Status**: Status pengajuan aktif (`Request`, `Approved`, `Completed`).
4. **Tombol Aksi**: 
   * **Edit (Icon Pensil)**: Memicu pembukaan modal konfirmasi persetujuan (*Confirm Approval*).
   * **Reject (Icon Silang)**: Menolak langsung pengajuan lembur.

### B. Modal Konfirmasi Persetujuan (Confirm Approval)
Popup modal yang muncul saat tombol *Edit* diklik oleh Manager:
1. **Status Dropdown**: Dropdown status baru, pilihan yang tersedia: `Approved`, `Pending`, `Cancel`.
2. **Notes Textarea**: Kolom input catatan/alasan dari atasan (contoh: mengapa disetujui atau ditolak).
3. **Tombol Aksi Modal**:
   * **Cancel**: Menutup modal tanpa menyimpan perubahan.
   * **Approval**: Menyimpan status dan catatan baru ke database.

---

## 2. Perubahan Skema Database (Database Alteration)
Berdasarkan temuan di mockup modal, terdapat kolom catatan baru (**Notes**) yang diinput oleh Manager. Oleh karena itu, kita perlu memodifikasi tabel `overtimes` agar memiliki kolom untuk menyimpan catatan tersebut.

### SQL ALTER untuk Menambahkan Kolom `notes`:
Jalankan perintah SQL DDL berikut di database Oracle Anda:
```sql
ALTER TABLE overtimes ADD notes VARCHAR2(255);
```

### Struktur Baru Kolom Tabel `overtimes`:
Kolom `notes` akan bersifat opsional (`NULL`) secara default karena baru terisi ketika diproses oleh atasan.

| Nama Kolom | Tipe Data | Constraint | Keterangan |
| :--- | :--- | :--- | :--- |
| ... | ... | ... | ... |
| **`notes`** | `VARCHAR2(255)` | `NULL` | Catatan/alasan persetujuan dari atasan (e.g. 'Sesuai dengan target sprint') |

## 3. Penyesuaian REST API & Validasi

### A. Penyesuaian REST API Payload (PATCH Request)
Ketika atasan menekan tombol **Approval** pada modal, frontend akan mengirim request PATCH ke backend:
* **HTTP Method**: `PATCH`
* **Endpoint**: `/api/v1/overtimes/:id/approve`
* **Request Body (JSON)**:
  ```json
  {
    "approvedBy": 101,
    "status": "Approved",
    "notes": "Sesuai dengan lembur rilis fitur di production."
  }
  ```
* **Expected Response (200 OK)**:
  ```json
  {
    "success": true,
    "message": "Overtime request approval status updated successfully",
    "data": {
      "overtimeId": 1,
      "employeeId": 100,
      "employeeName": "Steven King",
      "overtimeDate": "2025-06-09",
      "projectName": "WebDev I",
      "startTime": "07:00",
      "endTime": "09:00",
      "totalHours": 2.00,
      "status": "Approved",
      "approvedBy": 101,
      "approverName": "Neena Kochhar",
      "notes": "Sesuai dengan lembur rilis fitur di production."
    }
  }
  ```

## 4. Rencana Implementasi Perubahan Kode
1. **Database Migration**: Menjalankan migrasi DDL `ALTER TABLE` untuk menambahkan kolom `notes`.
2. **Repository Layer**: Memperbarui query insert/select pada `overtimeRepository.js` agar menyertakan kolom `notes`.
3. **Service Layer**: Memperbarui parameter input pada fungsi `approveOvertime(id, { approvedBy, status, notes })` agar turut menyimpan catatan ke database.
